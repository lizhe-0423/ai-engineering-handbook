# 智能备课怎样接进教师原有流程

[← 教师智能助手](README.md)

备课助手很容易做出一个演示。输入课题和年级，几秒钟后得到一份结构完整的教案。教师开始用时，问题才会出现。课程标准是哪一版，学校正在用哪套教材，这节课承接了前面什么内容，班级里又有哪些需要调整的地方，通用大模型都不知道。

生成教案只是备课中的一个动作。教师通常先确认教学目标，再选材料和活动，随后准备课件、练习与课堂提问。不同学校的文档要求会改变交付格式，教师也会在试讲或上课后继续修改。智能备课只有进入这条往返流程，才可能省下一部分重复劳动。

## 先建立一份可信的备课上下文

一次任务可以从教师选择学段、学科、教材版本和课时开始。系统据此加载课程标准、教材章节、校本资源和教师有权使用的历史材料。正式文件与个人资料要分层标记，版本和来源随片段一起进入后续流程。

旧教案不能整批丢进一个知识库就算完成。里面可能有过期要求、临时活动和只适合某个班级的安排。资料入库时要保留作者、适用范围和状态，教师删除或替换文件后，索引也要同步失效。跨校部署时先做租户隔离，语义检索排在权限过滤之后。

班级情况需要更谨慎。备课可能只需要掌握度分布和常见错误，不需要学生姓名与完整作答。能用聚合数据解决的问题，就不要把个人记录交给生成模型。教师确实要查看个别情况时，再通过有权限的学情工具按需查询。

## 让 Agent 处理步骤，不替教师定目标

备课 Agent 可以把任务拆开。先从正式资料中提取本课要求，再检索相关教学资源，随后生成活动与练习候选，最后检查各部分是否互相一致。每一步使用的输入和产物都单独保存，教师可以只重做其中一段。

教学目标由教师选择或确认。模型可以指出目标与课程材料的对应关系，也可以提醒某项活动没有覆盖目标。它不应悄悄新增一套目标，再用自己生成的练习证明这套目标已经完成。

题目生成也要调用题库与校验工具。系统先确认知识点、难度和题型，再生成候选题，随后检查答案、唯一性和材料依据。计算题可以用符号工具复算，已有题目要做相似度检查。开放性题目则需要教师查看立意、表述和评价方式。

## 编辑器比聊天框更重要

教师很少会接受一整份初稿，只在末尾点同意。产品需要让他替换一项活动，锁定一段内容，比较前后版本，还能追溯一句话来自哪份材料。局部修改后，系统只更新受影响的课件或练习，不能把教师已经确认的部分重新生成。

教师修改可以保存为个人偏好，比如课堂活动时长和常用表达。学校正式模板与学科规则需要经过指定人员发布。两类配置不能混在一起，否则一位教师的改法可能悄悄影响其他人。

导出也属于备课流程。教案、课件和练习应共享同一份任务状态，标题、课时和知识点保持一致。若系统只是分别生成三个文件，内容互相打架的概率很高。导出前再做一次引用、答案和版式检查，失败时保留可编辑内容，不要让教师重新开始。

课件生成的具体流程见[教师课件怎样从教学资料生成](courseware-generation.md)，继续讨论分页面内容、局部重生成和导出后验收。

## 复核责任要落到界面上

教师生成式人工智能应用相关指引一直强调结果复核。产品不能只在协议里写一句“AI 内容可能有误”。复核机制要出现在任务界面里。系统标出外部资料、低置信内容和仍未覆盖的教学目标，教师逐项处理后才能发布给学生。

涉及学生评价、敏感主题和版权不明材料时，流程应自动提高复核级别。模型无法找到可靠来源时，可以给出待补项，不需要用常识填满整份教案。一个诚实的空白，比一段无法核对的完整文字更省事。

## 衡量节省了哪一段工作

备课助手的使用次数只能说明入口有人点。更值得看的是教师在各步骤花了多久，哪些候选经常被删除，哪类资料经常召回错误，导出后是否还要大幅返工。教师连续使用一段时间后仍愿意保留的内容，通常比首次生成的满意评分可靠。

教学效果需要单独评价。教案写得快，不代表课堂学得好。可以由教师和教研员检查目标、活动与评价是否一致，再结合课堂后的作答与观察做小范围验证。没有证据时，只能说系统减少了某些准备工作，不能把它直接写成教学质量提升。

智能备课最终要把教师从重复查找和格式整理中解放一点，同时保留他对教学目标与课堂选择的控制。做到这一点，产品才像助手。只会源源不断地产生文档，它更像一台需要教师收拾残局的打印机。
