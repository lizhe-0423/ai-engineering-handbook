# 沙箱怎样隔离 Agent 的执行

[← AI Agent 学习路线](README.md)

Agent 需要运行脚本检查周报格式时，脚本可能读取文件、启动子进程或访问网络。工具权限允许执行脚本以后，还需要控制脚本实际能接触到的环境。

沙箱是为执行任务设置的隔离边界，可以限制文件、进程、网络、资源和执行时间。容器、虚拟机和其他机制都可以用于构建沙箱，具体隔离能力取决于配置与运行环境。本文讨论设计检查，不宣称某一种技术自动安全。

## 先划定任务需要的范围

假设周报检查脚本只需要读取一份草稿并返回章节检查结果。可以给它一个临时工作目录，只读挂载必要文件，限制输出目录，设置执行时限和内存上限。若它不需要网络，就不应默认继承所有网络访问能力。

| 边界 | 示例措施 | 要检查的问题 |
|---|---|---|
| 文件 | 限定可读写目录，限制挂载 | 符号链接或路径变化能否越界 |
| 网络 | 按需开放目标，限制出站 | 是否能访问不应访问的服务 |
| 进程 | 限制进程数量与权限 | 子进程能否逃出约束 |
| 资源 | 限制 CPU、内存、磁盘和时间 | 超限后能否回收 |
| 凭证 | 只提供当前操作所需的授权 | 是否被写入日志或产物 |

路径字符串检查有用，但不能单独防住符号链接、路径竞争或运行时权限配置错误。命令黑名单也无法覆盖所有表达方式。真正的文件和网络限制需要由执行环境落实。

## 隔离和可用性需要一起设计

项目可能需要编译器、依赖包、测试数据和服务替身。沙箱限制资源边界，项目环境负责准备必要工具和配置；否则 Agent 可能不断尝试安装缺失依赖，或者误把生产系统当测试环境。

需要联网下载依赖时，应明确允许范围并管理依赖来源。用户数据与外部内容都可能包含恶意指令，应用仍要限制工具权限和处理结果；沙箱不保证模型理解正确，也不替业务系统完成授权。

## 生命周期与失败处理

一次执行应有创建环境、装载必要文件、运行、收集受控结果和清理阶段。脚本超时、进程退出或工作节点故障时，平台需要终止相关进程并回收资源。清理失败要可观测，不能只在界面显示“任务结束”。

不要把长期凭证直接写入工作目录。需要调用外部服务时，优先提供范围和有效期受限的授权，并确保执行日志与产物不包含凭证。对生产写入或发送操作，仍需单独的审批与业务幂等。

## 如何验证边界

在隔离测试环境中检查目录越界、符号链接、未经允许的网络访问、子进程逃逸尝试、资源超限和清理失败。比较实际生效配置与环境声明，定期修复运行时和依赖漏洞。没有完成这些测试时，不能仅凭“放进容器”就声称具备强隔离。
