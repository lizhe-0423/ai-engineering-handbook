# 插件怎样安装、卸载并释放资源

[← AI Agent 学习路线](README.md)

任务系统接入 Agent 时，可能同时提供工具、说明文件和初始化配置。逐项手动安装容易漏掉依赖；移除时，已经注册的工具和后台连接也需要一起处理。插件可以把这些资源按一个可管理的单元组织起来。

插件的具体结构由宿主应用定义。本文使用虚构的任务系统插件说明生命周期，不代表某个产品的实际插件格式。

## 插件交付什么

一个插件可以包含身份与版本信息、工具声明、Skill、配置项和需要初始化的资源。安装时，宿主读取清单，检查兼容版本和来源，随后创建资源并注册允许使用的工具。

| 阶段 | 需要处理 |
|---|---|
| 安装 | 检查来源、配置、版本与依赖 |
| 启用 | 初始化连接，注册工具和相关能力 |
| 运行 | 按任务权限调用，记录错误与版本 |
| 停用 | 停止接收新调用，处理在途执行 |
| 卸载 | 注销工具，关闭连接、线程和临时资源 |

插件不一定需要独立进程或数据库。少量固定能力可以通过应用代码注册；插件适合需要独立安装、升级或移除的一组能力。

## 安装失败不能留下半套状态

假设任务插件要注册两个工具，第二个工具与已有名称冲突。宿主应拒绝或明确处理冲突，并回滚此次安装已创建的注册和资源，不能留下一个对外可见、但初始化不完整的插件。

如果操作跨进程或外部服务，无法用单个事务回滚全部步骤，需要记录安装进度、补偿动作和异常状态。安装重试应识别已完成部分，不重复创建外部资源。

[Java ServiceLoader](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/ServiceLoader.html)提供发现服务实现的一种机制。它不自动提供插件权限控制、升级回滚或进程隔离，这些仍需宿主设计。

## 停用和在途调用

停用先阻止新调用，再按照规则等待或取消已有执行。取消只是请求，外部系统可能已经接受写操作。宿主需要记录结果，必要时对账。旧版本处理中的任务可以在兼容条件下完成；若发生安全事件，应及时撤销权限并检查未完成的副作用。

卸载时关闭连接、定时器和后台线程，清理工具注册和缓存。多实例部署需要共享权威状态，避免某些实例还在向模型提供已停用的工具。[工具注册表](tool-registry-lifecycle.md)展开了状态检查与并发下线。

例如插件的第一版仍有一个只读查询在执行，此时管理员安装第二版。宿主可以先禁止第一版接收新请求，让已开始的查询在限定时间内完成，再释放第一版连接；新任务使用第二版契约。如果第二版初始化失败，就按实际兼容策略回退或保持停用，不能把失败的新版本展示为可用。

## 加载隔离与安全边界

类加载器或模块空间可以帮助隔离依赖版本，但不能作为不可信代码的完整安全沙箱。插件拥有的文件、网络和进程权限需要由运行环境限制。安装前还应检查来源、版本、依赖和更新方式；声明中的“只读”不能代替业务权限检查。

检查场景包括名称冲突、初始化失败、升级不兼容、卸载时有在途调用、后台线程无法退出和多个实例缓存不一致。测试时应同时观察注册表、资源占用和外部副作用，而非只看插件列表是否消失。
