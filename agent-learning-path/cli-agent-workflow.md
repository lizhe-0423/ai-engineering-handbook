# CLI Agent 怎样进入终端工作流

[← AI Agent 学习路线](README.md)

开发者希望在终端里让 Agent 查找项目文件、整理检查结果，或者在脚本中发起一次有限的任务。命令行接口，也就是 CLI，可以提供交互式会话和单次执行两种入口。

CLI 负责接收输入、展示状态和向操作系统返回结果。模型选择工具、运行沙箱和处理权限，仍由背后的 Agent 应用负责。下面的命令仅用于说明界面设计，不代表现有产品支持这些参数。

## 两种入口有不同要求

交互式模式适合多轮澄清，用户能看到过程并继续补充。单次模式适合脚本调用，需要明确输入、输出格式、超时和退出状态，不能把需要人回答的问题藏在一个永远等待的进程里。

```text
示例命令形式
agent-example chat
agent-example run --task "检查当前项目的文档链接"
```

具体命令、参数和安全限制取决于实现。CLI 需要提供帮助信息，并明确哪些参数必填；[Python argparse 文档](https://docs.python.org/3/library/argparse.html)展示了命令行参数和帮助的一种实现。

## 工作目录与输入输出

应用应明确当前工作目录与可访问范围。用户从一个项目目录发起任务，Agent 不应因为模型生成了相对路径就自动获得整个电脑的写权限。路径规范化、符号链接和实际文件访问仍需由执行环境检查。

交互文本和机器可解析的结果可以分开，例如将结果写入标准输出，将诊断信息写入标准错误；具体约定由 CLI 定义。退出码应区分成功、任务失败、等待用户和被取消，让调用脚本能判断后续步骤。不能因为程序正常退出就认定用户任务已经完成。

例如单次任务需要用户确认才能继续时，非交互模式可以输出“等待确认”的机器可读状态并结束，而不是一直阻塞。具体退出码应由 CLI 的文档明确约定。调用脚本按这个约定处理，不能只看模型回复里是否包含“完成”。

## 取消、凭证与自动化

用户按下中断键时，应用停止启动新的工具调用，并尽力通知运行中的子进程。远程请求可能已经提交，必要时核对结果。退出前保存可恢复状态和必要诊断，不能在取消时默默执行未确认的后续写入。

凭证不要放进命令参数或日志，命令行历史和进程列表可能暴露参数。使用受控凭证提供方式，按操作限定权限和有效期。非交互环境遇到需要授权或缺少输入的步骤，应返回明确状态，不假设用户已同意。

测试应覆盖无输入、无权限、超时、中断、输出管道关闭、错误退出和工作目录变化。需要执行不可信代码时，还要结合[沙箱隔离](agent-sandbox-isolation.md)。
