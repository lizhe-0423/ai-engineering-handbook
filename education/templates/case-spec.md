# 案例规格

复制此表，先填可验收的任务，再选模型和框架。未知项保留“待确认”。

| 项目 | 填写内容 |
|---|---|
| 案例名称、ID、版本 | |
| 当前状态 | 草稿 / 待审核 / 已确认 |
| 参与者与使用场景 | 谁在什么时候需要完成什么动作 |
| 问题与当前做法 | 原来的处理方式，具体卡点 |
| 输入与可用范围 | 数据类型、访问来源、资料与材料版本 |
| 预期产物 | 证据 / 候选解释 / 评分草稿 / 正式结果 |
| 允许动作 | 回答、确认、交教师、重试等有限集合 |
| 禁止与不适用条件 | 何时不能调用此案例 |
| 判断规则 | 谁根据什么证据判定可用 |
| 人工接手 | 接手者、触发条件、转交材料 |
| 正常样本 | 输入、预期结果与理由 |
| 失败样本 | 至少两条，分别写预期动作 |
| 运行入口与环境 | 命令、版本、依赖、模型是否启用 |
| 已完成验证 | 链接到实际运行记录 |
| 未验证能力 | 不由现有结果支持的结论 |
| 来源与使用范围 | 原创、合成、公开引用或授权素材 |

检查一次：另一位读者能否只凭这张规格找出输入、接手人和成功条件？
