# 答疑评测与向量索引治理设计

## 目标与边界

本轮修改同时处理两类问题。数字名师文章补齐 Agent 流程、检索评测和业务兜底。数据库与向量库同步、历史全量去重、灰度迁移和数据飞轮属于通用知识工程能力，放在企业级 AI 生产平台下单独成篇。

新文章以专升本题库为贯穿案例，只保留通用业务规则和工程方法，不写真实公司名、数据量、表结构和未公开流程。

## 方案选择

本轮考虑了三种组织方式。

1. 全部追加到数字名师答题文章。优点是上下文集中，缺点是实时答疑会被数据迁移细节打断。
2. 在企业级 AI 生产平台下写独立文章。数字名师文章保留必要摘要与链接，数据工程主线完整展开。
3. 在数字名师目录下新增题库专篇。优点是教育业务更突出，缺点是以后教案、课件和企业文档会重复一套同步与迁移机制。

采用第二种。它符合仓库对业务方案和系统能力的目录划分，也能保留题库对去重语义的特殊要求。

## 数字名师答题文章

### 受控且可插拔的 Agent

增加一张 Mermaid 流程图。会话状态与范围检查是必经节点，OCR、同题检索、教师知识库、计算工具和重排根据输入类型按需启用。输出检查与回答或拒答出口保留在主流程里。

可插拔节点使用统一契约，至少声明输入、输出、版本、超时、失败出口和可见的状态字段。Agent 只能从运行配置允许的节点中选择，不在运行时自由发明新步骤。

### 分层评测

拍搜层使用 `Top1 Accuracy`、`Hit@K`、`Recall@K`、`Precision@K` 和 `MRR@K`。原题只有一个标准匹配时，重点看 `Top1 Accuracy`、`Hit@K` 和 `MRR@K`。教师知识库存在多个可用片段时，再重点看 `Recall@K`、`Precision@K` 与有分级相关性的 `nDCG@K`。

入口识别、意图判断、检索、生成、拒答和教学效果分开验收。文章给出一个小例子说明 MRR，不设置没有实测依据的通用及格线。

### 业务兜底

保留传统题库维护流程。运营人员处理未命中、错命中和高风险候选，人工录入标准题、原图、答案、解析、出处和题目关系。业务数据入库后再由同步任务更新检索索引，不让运营工具直接修改线上向量。

## 向量索引治理文章

### 业务数据是事实源

关系数据库或文档存储保留题目、版本、原图、来源、状态和审计信息。向量库保存业务主键、版本、内容哈希、模型版本、向量与过滤字段，承担可重建的检索索引职责。

### 增量同步与全量重建

增量同步使用 Outbox 或 CDC 事件，通过业务主键、单调版本和内容哈希做幂等 upsert。删除以 tombstone 事件传递，同步失败进入重试与对账。

全量处理不在线修改当前集合。系统在高水位生成业务快照，后台构建新索引，重放高水位以后的增量事件，然后检查数量、版本、样本和检索评测。新索引先进入影子读取和小范围灰度，最后通过别名或配置原子切换。旧索引保留一段观察期，提供回滚。

### 题库去重是业务判断

文本一样不等于业务对象一样。同一道关于 bit 与 byte 的题可以出现在不同试卷、页码和考试批次中。系统保留各自的题目实例，再把它们关联到一个可选的标准题或同题组。

去重先用归一化哈希找完全一致候选，再用关键词、shingle、向量和图片特征找近似候选。规则与模型只负责缩小人工复核范围。复核结果分为同题、变式题、同知识点和不相关，不直接物理删除历史数据。

### 删除、备份与线上安全

业务数据进入禁用或逻辑删除后，向量索引先通过状态过滤停止返回该记录。物理清理延后到保留期结束，并保留可审计的 tombstone。全量处理前先保留快照或可重建的源数据，新旧索引并存期间不让后台任务争抢线上查询资源。

### 数据飞轮与评测集

无结果、搜错题、学生选中的真实原题、运营修正和新题收录进入统一复核队列。确认后先修改业务数据，再由同步流程更新向量索引。

经过人工确认且代表真实失败模式的样本可以进入候选评测集。评测集保留版本、标注依据、来源时间和数据分区，同时维护一份固定回归集与一份持续更新的近期集。用于训练或阈值调整的数据不直接进入同一版评测集。

- 向量索引文章增加增量同步、全量重建、灰度切换和回滚流程图。

## 验收

- `qa.md` 的 Agent 图明确区分必经与可选节点。
- 检索指标都给出计算含义与适用场景，不把相似度分数当成准确率。
- 新文章能从业务数据追到向量点，也能从向量点回到业务版本。
- 全量迁移不直接覆盖线上索引，去重不直接删除历史题目。
- 同步、去重、灰度和数据飞轮都有对应的失败出口和回滚方式。
