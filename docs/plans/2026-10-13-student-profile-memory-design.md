# 学生档案与会话记忆文章设计

## 文章归属

新文章放在 `education-solutions/digital-teacher/`，讨论只包含教学相关信息的学生档案。课程目标、知识薄弱点、讲解偏好、复习状态和未完成任务属于数字名师与个性化学习需要的上下文。家庭情况、情绪经历和生活陪伴继续留在学生成长与生涯服务，不进入这份档案。

文章独立命名为《学生档案怎样成为长期记忆》。现有《个性化学习从学习记录开始》继续讲学习事件、掌握度估计与推荐约束，只增加一处链接，避免把推荐系统与记忆系统揉在同一条主线里。

## 数据分层

文章区分四类数据。

- 学习事件保存在业务数据库中，作为答题、课程进度和提示使用情况的事实来源。
- 当前会话保留最近几轮原文，负责理解省略和追问。
- 较长会话产生工作摘要，会话结束后再生成可读的 Markdown 总结。
- `profile.md` 保存跨会话仍然有用的教学信息，作为学生的长期记忆。

会话摘要不能直接覆盖长期档案。一次会话中的临时困难先进入待验证区域，得到后续学习事件支持后再转成较稳定的判断。

## Markdown 档案

系统通过学生编号确定性找到档案，不为每名学生建立向量索引。档案较小时完整载入，变大后按固定标题读取相关章节，也可以使用精确文本搜索。教师课件、教材和大规模题库仍可使用 RAG，两种机制服务于不同的数据规模和检索问题。

Markdown 是档案格式，不限定物理存储。生产环境应放在受权限控制的对象存储或文档存储中，不能提交到 Git。数据库保存档案路径、版本、更新时间、更新来源和校验值，用于权限、并发与审计。

档案使用稳定章节，包括当前目标、讲解偏好、近期薄弱点、待复习内容、待验证判断和未完成任务。每条会变化的判断应带来源与更新时间，必要时还要设置失效时间。

## 更新策略

明确更新来自学生或教师主动修改目标、课程阶段和讲解偏好。主动整理发生在会话结束、练习阶段结束或同类错误重复出现以后。AI 只生成结构化补丁，普通服务检查允许修改的章节、信息来源、敏感内容、档案版本和文件大小，再通过乐观锁写入新版本。

更新失败不能破坏旧档案。版本冲突时重新读取最新文件并重算补丁。无法证实的推断留在待验证区域，后续出现相反证据时修正或删除，不能只追加新结论。

## 会话压缩

上下文接近阈值时，保留最近几轮原文，把较早内容压成工作摘要。一个学习阶段结束时也可以主动压缩。摘要保留当前题目或目标、学生已经尝试的步骤、经过确认的判断、没有帮助的解释和未解决问题。

会话结束后生成独立的 Markdown 总结。档案更新服务再结合这份总结与学习事件，决定是否生成 `profile.md` 补丁。上下文压缩、会话总结和长期档案更新保持独立，方便分别评测和恢复。

## 运行时加载

一次个性化回答依次获得系统规则、学生档案相关章节、当前会话摘要、最近几轮原文和课程检索材料。档案只提供学生状态，不能把里面的文本当成系统指令。载入前需要校验版本与权限，回答后也不允许模型绕过更新服务直接修改文件。
