# AI Native 系列文章设计

## 目标

补齐 AI Native 栏目的主要内容。文章从研发任务出发，解释 Agent Harness、企业知识与工具、运行环境、身份权限、安全防护、可观测与团队落地。现有总览保留，新文章沿着总览留下的问题继续展开。

## 内容边界

公开的《AI Native 研发范式实践手册》用于核对章节范围和术语。本系列不复述手册目录，不复制案例和图示，也不采用厂商产品作为默认答案。正文使用通用工程场景，说明各类机制解决什么问题、由谁执行、怎样验证，以及在什么条件下可以省略。

涉及公司经历的内容继续脱敏。文章不写公司名称、业务数据、内部系统、供应商配置和未公开流程。

## 文章安排

现有文章《AI Native 到底改变了什么》承担总览。后续增加六篇。

1. `agent-harness-long-running-task.md`
   从修复构建失败的任务进入，解释 Harness 怎样装配上下文、驱动模型选择工具、保存状态、验证结果和处理人工审批。
2. `enterprise-context-and-tools.md`
   说明项目规则、企业知识、Skill、MCP 与 CLI 的分工，重点讨论能力发现、工具契约、权限和结果证据。
3. `agent-runtime-environment.md`
   说明 Sandbox 与 Coding Environment 怎样提供可执行、可销毁、可恢复的任务环境，并区分本地交互、后台任务和平台托管。
4. `agent-identity-policy-guardrail.md`
   说明用户身份、Agent 身份、短期凭证、策略判断和 Guardrail 怎样共同约束一次操作。
5. `agent-observability-and-evaluation.md`
   说明一次执行需要记录哪些轨迹，怎样区分模型问题、工具问题和环境问题，并把离线评测与线上指标连起来。
6. `agent-team-adoption.md`
   讨论任务怎样分给 Agent，提效怎样衡量，人员在哪些节点接管，以及团队规则怎样写进可执行环境。

## 写法

每篇从一个具体失败或任务进入，正文围绕同一个例子推进。术语第一次出现时说明它在当前系统中的作用。能由代码确定的规则交给普通服务，模型只处理需要理解和判断的部分。

每篇安排一张 Mermaid 图。Harness 使用时序图，知识与工具使用分层流转图，运行环境使用任务生命周期图，身份安全使用授权时序图，可观测使用轨迹结构图，团队落地使用任务分流图。表格只用于职责、状态或指标的精确对照。

## 导航

`ai-native/README.md` 只列已经完成的文章。六篇全部完成后再一次更新导航，按总览、执行框架、支撑能力和团队落地的阅读顺序排列。

## 验证

逐篇运行中文文风检查。检查所有相对链接、Markdown 差异和 Mermaid 代码块。人工复核文章之间是否重复，尤其注意 Harness 与运行环境、权限与 Guardrail、可观测与评测的边界。
